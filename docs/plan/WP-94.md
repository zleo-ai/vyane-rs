# WP-94 — redacted effective permission diagnostics

## 目标

让现有 `vyane check` 与 MCP `vyane_check` 能说明多层权限配置最终施加了
什么上限，而不要求操作者逐层手工推导，也不暴露路径、域名、命令、
环境变量名或原始规则。

本包只增加静态、只读诊断，不改变 Harness、Native/Canto 执行或 approval
语义。

## 决策模型

- CLI Harness 报告配置层数量和所有层合成后的 `max_sandbox`。
- Native/Canto 对每个能力轴只报告三态：
  `unrestricted_by_config`、`bounded`、`disabled`。
- `unrestricted_by_config` 只表示配置没有收紧该轴；它不代表请求自动获得
  能力。Native 可选工具仍必须由请求显式启用。
- 任一 Native 配置层省略可选能力时，该能力为 `disabled`；所有层都包含时
  只报告 `bounded`，不尝试把参数规则误报成一个通用 grant。
- 工具 allow/ask/deny 仅报告策略层数和规则总数，不返回匹配器或 effect。
- 诊断使用已经加载的配置，不探测进程、网络或 provider。

## 验收门

1. 没有权限配置时，Harness 上限为 `full`，Native 各轴明确为
   `unrestricted_by_config`。
2. 多个 Harness 层报告严格合成后的上限。
3. Native 可选轴在任一层省略时报告 `disabled`，全层存在时报告
   `bounded`。
4. 新增的 JSON 权限 DTO 与 CLI 权限行都不包含权限配置中的路径、域名、
   命令、环境变量名或原始工具规则；CLI 既有的配置文件与 provider
   environment 诊断不在本包内改变。
5. 运行全仓 format、Clippy、test，并通过独立评审与云端 CI。
