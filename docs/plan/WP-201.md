# WP-201 — CLI human `vyane check` section pure formatters + tests

## Outcome

Human `vyane check` non-permission sections project through pure helpers:
`format_check_config_files`, `format_check_provider_line`,
`format_check_profile_line`, `format_check_harness_line`,
`format_check_profile_env_line` (terminal-safe free text). Permission block
remains WP-193's pure path.

## Motivation

After WP-193 extracted the redacted permission summary, the rest of `vyane check`
still used ad-hoc `println!` without pure helpers or unit coverage.

## Acceptance

1. Config files / providers / profiles / harnesses / profile environment human
   rows use the pure formatters (permissions still `print_permission_check`).
2. Free text paths/ids/vars are terminal-safe; states use fixed tokens
   (loaded|missing, available|missing, present|missing).
3. Unit tests drive the shipped formatters.
4. Local gates and independent review pass; no CI isolation train.
