# WP-190 — CLI human route result pure formatter + tests

## Outcome

Human `vyane route` projects the resolved profile and `RouteDecision` through
pure `format_route_result` / `print_route_result`. Unit tests drive the shipped
formatter with real decision values (tier/effort as_str, score precision,
terminal-safe free text).

## Motivation

After WP-179–189 locked human pure helpers on task/workflow/session/goal/
continuity surfaces, `vyane route` still printed nine labeled lines via
ad-hoc `println!` without a pure helper or unit coverage.

## Acceptance

1. Human path uses `print_route_result` → `format_route_result` (JSON path
   unchanged).
2. Lines cover profile, provider, model, tier, effort, score (three decimals),
   tag, intent, reason — matching prior human layout.
3. Free-text fields (profile, provider, model, tag, intent, reason) are
   terminal-safe; tier/effort use domain `as_str`.
4. Unit tests call the shipped formatter with real `RouteDecision` values.
5. Local gates and independent review pass; no CI isolation train.
