# WP-88 — Layered native permission ceilings

## Outcome

Let operators adjust every delivered native permission axis through ordinary
Vyane configuration without allowing a repository or API request to weaken a
restriction from another layer.

The AgentRun request remains the only place that opts into an optional tool.
Configuration supplies ceilings, not automatic grants.

## Configuration sources

Vyane reads independent ceilings from:

1. the user config;
2. the project `.vyane/config.toml`;
3. an explicit `--config` file when that replaces the normal user/project
   stack;
4. the operator-managed file named by `VYANE_MANAGED_NATIVE_CONFIG`.

The managed file accepts only a single `[native_permissions]` tree. Provider,
profile, secret, or unrelated configuration in that file fails closed.

Each file either omits `[native_permissions]` and contributes no ceiling, or
provides one complete ceiling. Inside a present ceiling, omitting an optional
axis denies that axis. The section still grants nothing until the AgentRun
request explicitly asks for the capability.

```toml
[native_permissions.filesystem_read]
exclude = [".env*", ".git", "private/**"]

[native_permissions.web_fetch]
allow_domains = ["docs.rs"]
max_fetches = 2
max_response_bytes = 262144
max_redirects = 2
```

## Monotonic composition

- Read/write path exclusions are combined. A later layer cannot remove one.
- A requested command must be a subset of an allowed program and argument
  prefix, and its timeout cannot exceed the ceiling.
- A ceiling that allows command execution cannot add read exclusions. The
  current read-only command sandbox mounts the full admitted workspace, so
  that combination would let a command bypass the file-tool exclusions and
  fails during config loading.
- A requested command-network host/port set must be a subset of the ceiling.
  Route, connection, byte, and timeout limits cannot be widened.
- Hosted search must use the same target. Domain scope, search count, and
  context size can only narrow.
- Direct fetch domains and count/response/redirect limits can only narrow.
- A request for an optional axis omitted by any present ceiling is rejected
  before workspace probing or a model request.
- Invalid ceilings fail during config loading. Invalid combinations or request
  widening fail during native submission.

The effective request is frozen into the existing native spool and policy
digest. Recovery and exact retry therefore use the resolved permission set,
not a mutable config file.

## Verification

- Config tests retain user/project ceilings independently instead of applying
  normal higher-wins replacement.
- Managed-file tests reject unrelated sections and invalid policies.
- Composition tests cover no implicit grants, accumulated exclusions,
  command-prefix narrowing, command-network host/port narrowing,
  hosted-search narrowing, invalid command/read combinations, and request
  widening.
- Daemon request tests prove multiple config ceilings are applied before
  native host admission.
- Existing native filesystem, command, command-network, search, and fetch
  tests remain green.
- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- The exact PR head receives independent cross-model review and every required
  GitHub check before merge.

## Explicit exclusions

- no writable command profile;
- no automatic approval or approval resume;
- no config layer that automatically enables a tool;
- no native session resume, checkpoint, or session commit;
- no remote management distribution or OS-level protection for the managed
  config path.

## Current implementation status

The isolated branch contains the typed config shape, monotonic resolver,
managed-file loader, daemon admission wiring, tests, and public documentation.
It is not delivered until the exact committed head passes independent review
and every required GitHub check.
