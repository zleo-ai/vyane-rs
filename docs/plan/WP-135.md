# WP-135 — multi-thread MockServer daemon client unit fixtures

## Outcome

Run MockServer-backed daemon client unit fixtures on a two-worker Tokio runtime
so wiremock-backed submit/control/response-bound paths stay independently
schedulable under suite load.

Production daemon client behavior does not change.

## Motivation

Protocol and CLI acceptance MockServer suites were multi-threaded in prior WPs.
Daemon client HTTP unit fixtures still used the default current-thread runtime.

## Acceptance

1. MockServer-backed daemon client unit fixtures use two Tokio workers.
2. Existing assertions remain unchanged.
3. No production code changes.
4. Local targeted runs, gates, review, PR CI, and exact merged-main CI pass.
