# WP-92 — frozen native target failover

## Goal

Let one fresh/sessionless native AgentRun use the target selector's resolved
OpenAI Chat failover chain without weakening the existing tool-side-effect
boundary.

This package extends the vyane-rs native/Canto execution lane. It does not
change the generic CLI harness adapters, add approval resume, or add native
session continuity.

## Contract

- A native submission accepts one to sixteen resolved targets.
- Every leg must be a direct OpenAI Chat target with no external harness and a
  concrete endpoint.
- The primary snapshot remains the existing `target`; ordered additional
  snapshots are frozen as `failover_targets`.
- Provider, protocol, model, authentication shape, endpoint-routing digest,
  and generation parameters for every leg are covered by the durable native
  policy digest.
- Resident execution resolves the selector again and requires the complete
  current chain to match every frozen snapshot in order before the first model
  request. Addition, removal, reordering, route drift, model drift, parameter
  drift, or unsupported legs fail closed without a model request.
- Between attempts, the operation consults only
  `ErrorKind::failover_eligible()`. It does not reimplement the taxonomy.
- A target-level model timeout returned before the fixed run deadline retains
  `ErrorKind::Timeout` and may advance to the next target. The outer fixed run
  deadline, cancellation, and a typed tool timeout are terminal for the whole
  chain.
- Once an allowed known tool may have been polled, `NativeTurnDriver` returns a
  typed non-failover stop for later model/tool errors. The operation never
  advances to another target after that boundary.
- Every attempt starts from the original system/user messages. No partial
  assistant conversation from a failed target is transferred to another
  provider.
- The exact terminal retry contract remains digest-bound: a changed target
  chain conflicts instead of recreating native input or issuing another model
  request.

## Compatibility

The native spool schema advances to 11. Schema-10 inputs remain readable only
when `failover_targets` is empty. Older schema compatibility keeps its existing
capability restrictions.

## Verification

- unit tests cover chain bounds, schema-10 compatibility, target-chain digest
  coverage, and exact ordered matching;
- resident HTTP acceptance proves a failover-eligible primary failure reaches
  the secondary and commits its answer;
- resident HTTP acceptance proves a primary failure after tool activity never
  reaches the secondary;
- config/route drift is rejected before either endpoint;
- exact retry with target-chain drift conflicts without another request;
- formatting, Clippy, parity validation, workspace tests, independent review,
  and every required cloud check pass on the exact merged head.

## Explicit exclusions

- no failover after tool side effects;
- no cross-target conversation transfer;
- no per-leg deadline reset;
- no native session/checkpoint or approval resume;
- no change to web-search target semantics;
- no private route, credential, or deployment material.
