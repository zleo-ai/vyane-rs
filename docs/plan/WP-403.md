# WP-403 — Pure GoalContinuityStepStatus on continuity next

## Outcome

CLI `goal continuity-next` logs pure `format_goal_continuity_step_status_line`
for the handoff plan's next-ready step (when present) and, when the projected
next action names a step_id, that step's durable status as well.

## Motivation

WP-356 published pure continuity step status lines. WP-401 wired overall
continuity status/mode on next-action projection; step-level kinds were still
hostless on the CLI path.

## Acceptance

1. When continuity state exists and `next_ready_step` matches a plan step, log pure step-status + `status = as_str`.
2. When `next_action.step_id` matches a plan step (and is not the same as next_ready if already logged, still ok to log twice if different), log pure step-status + `status = as_str`.
3. Clear `#[allow(dead_code)]` on `format_goal_continuity_step_status_line`.
4. JSON/human bodies unchanged.
5. Local gates and independent review pass.
