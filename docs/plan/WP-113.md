# WP-113 — multi-thread remaining MockServer native acceptance fixtures

## Outcome

Run every remaining `daemon_agent_acceptance` fixture that starts Wiremock on a
two-worker Tokio runtime so mock targets and control-plane polling stay
independently schedulable after earlier acceptance fixtures in the same process.

Fixtures that already used `multi_thread` (mixed lanes, web-search, failover)
are unchanged. Process-only fixtures without Wiremock stay on the default
runtime. Kill/restart settlement fixtures that only need a delayed mock target
keep the default runtime so wall-clock lease expiry sleeps are not perturbed
by extra multi-thread suite load.

Production daemon, native lane, and timeout behavior do not change.

## Failure evidence / motivation

WP-108/111/112 fixed exact main/coverage/macOS failures where current-thread
acceptance fixtures starved Wiremock during status polling or multi-mock
failover. Several sibling fixtures in the same binary still use the default
current-thread runtime with MockServer plus terminal/hang paths. Under the
serialized CLI suite that is the same scheduling class as the proven failures.

This package preemptively aligns those fixtures without widening production
budgets or assertions.

## Acceptance

1. Every `daemon_agent_acceptance` test that constructs a `MockServer` uses an
   explicit two-worker Tokio runtime.
2. Existing terminal budgets and assertions remain unchanged.
3. No production code changes.
4. Local full-binary runs, gates, independent review, PR CI, and exact
   merged-main CI pass.
