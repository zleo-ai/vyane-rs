# WP-115 — multi-thread multi-mock CLI acceptance failover fixtures

## Outcome

Run multi-MockServer CLI acceptance failover/stream fixtures on a two-worker
Tokio runtime so primary/secondary targets stay independently schedulable under
the serialized CLI suite.

Production CLI dispatch and workflow behavior do not change.

## Motivation

WP-111–114 covered daemon AgentRun acceptance and native unit multi-mock
fixtures. CLI acceptance still had multi-mock failover paths on the default
current-thread runtime. Align them to the same scheduling class.

## Acceptance

1. Multi-mock CLI acceptance failover/stream fixtures use two Tokio workers.
2. Existing assertions remain unchanged.
3. No production code changes.
4. Local targeted runs, gates, review, PR CI, and exact merged-main CI pass.
