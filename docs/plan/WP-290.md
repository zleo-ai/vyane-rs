# WP-290 — PermissionRuleError and ToolRegistryError kind tokens

## Outcome

`PermissionRuleError` and `ToolRegistryError` publish snake_case kind-only
`as_str` tokens (payloads such as argument names stay out of the token).

## Motivation

Native tool permission rule construction and registry admission are P1 ask
surfaces. Failures carry thiserror Display prose; operators need closed kinds
for diagnostics without free-form paths/names.

## Acceptance

1. `PermissionRuleError::as_str` covers all variants kind-only
   (`empty_tool_pattern`, `invalid_argument_regex`, `floor_rule_must_deny`, …).
2. `ToolRegistryError::as_str` covers all variants kind-only
   (`empty_name`, `name_too_large`, `unsafe_name`, `duplicate`).
3. Unit tests lock multi-word tokens and assert argument names stay out of
   `as_str` for `InvalidArgumentRegex`.
4. Local gates and independent review pass.
