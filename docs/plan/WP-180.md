# WP-180 — CLI human durable `task status` pure formatter + failure_code tests

## Outcome

Human durable `task status` goes through a pure `format_durable_task_status`
helper that `print_durable_task_status` (and thus `run_task_list`'s durable
status path) uses. Unit tests drive the shipped formatter with real
`TaskRecord` + `FailureCode` values, locking snake_case `failure:` lines when
present and no invented failure line when absent.

## Motivation

WP-179 closed the human **list** gap for `failure_code`. Durable **status**
already printed `failure:` but only via untestable `println!`s — no pure
formatter and no unit coverage of the FailureCode → human path (unlike WP-178
workflow status).

## Acceptance

1. `print_durable_task_status` is a thin wrapper over `format_durable_task_status`.
2. When `TaskRecord.failure_code` is `Some`, human text contains
   `failure:    <snake_case>` from the real `FailureCode` Display.
3. When the code is `None`, no `failure:` line is invented.
4. Unit tests call the shipped formatter with `TaskRecord` values (not a re-implementation).
5. Local gates and independent review pass; no CI isolation train.
