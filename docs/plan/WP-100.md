# WP-100 — stabilize daemon terminal polling

## Outcome

Keep daemon AgentRun acceptance polling bounded without treating one transient
loopback transport timeout as the terminal result.

Production daemon behavior and endpoint semantics do not change.

## Failure evidence

The same 15-second `GET /v1/agent-runs/{id}` client timeout appeared under CI
and repeated local suite load in different Process and Native tests. Each
individual failing scenario passed repeatedly in isolation, so the failure was
not tied to one execution backend.

The fixture created a new HTTP client for every 50-millisecond poll and
immediately panicked on one request timeout. Its nominal terminal budget was
therefore not an actual total retry budget.

## Acceptance

1. One client is reused for a terminal polling session.
2. Each status attempt has a short timeout; timeout and connect errors retry
   only inside the existing total terminal budget.
3. Persistent unavailability still fails with the daemon log, and malformed
   responses still fail immediately.
4. The full serialized daemon acceptance suite passes repeatedly.
5. Format, Clippy, workspace tests, parity, independent review, and cloud CI
   pass on the exact committed head.
