# WP-189 — CLI human continuity next-action pure formatter + tests

## Outcome

Human `vyane goal continuity-next` projects the WP-79 next-action contract
through pure `format_continuity_next_action` (snake_case action/command tokens,
not Debug). Domain enums gain `as_str`/`Display` aligned with serde rename.

## Motivation

The continuity next-action projection already had durable fields and a JSON
path, but the human path printed `{:?}` for the action kind and omitted
revision / quota / optional command-step-approval fields operators need.

## Acceptance

1. Human path uses `format_continuity_next_action` (no Debug for action kind).
2. Action and optional command tokens are snake_case (`decide_approval`,
   `continuity_decide`, …) via domain `Display`.
3. Always prints goal, revision, quota, action, reason; optional command/step/
   approval lines only when present; goal/quota/step/approval/reason are
   terminal-safe.
4. Unit tests drive the shipped formatter with real `GoalContinuityNextAction`
   values (optional-field omission included).
5. Local gates and independent review pass; no CI isolation train.
