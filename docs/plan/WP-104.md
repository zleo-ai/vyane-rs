# WP-104 — checkout v6 and explicit CI token floor

## Outcome

Remove the Node.js 20 action-runtime deprecation from CI and release jobs while
keeping source checkout immutable and least-privileged.

No Rust, product, release-authorization, or runtime permission behavior changes.

## Evidence

GitHub Actions annotated every exact PR and main run with a warning that the
repository's `actions/checkout` v4 references target deprecated Node.js 20 and
were being forced onto Node.js 24.

The official `actions/checkout` release and repository documentation identify
v6.0.2 as the current stable release. It uses Node.js 24, moves persisted
credentials under `RUNNER_TEMP`, and requires runner v2.329.0 for authenticated
Git operations from Docker container actions. These workflows use
GitHub-hosted runners and no Docker container action consumes checkout
credentials.

The v6.0.2 tag resolves to the verified official commit
`de0fac2e4500dabe0009e67214ff5f5447ce83dd`.

## Acceptance

1. Every `actions/checkout` use in CI and publish workflows pins that exact
   v6.0.2 commit; the release-gate self-test rejects any floating or mismatched
   checkout reference.
2. The ordinary CI workflow explicitly grants only `contents: read`.
3. Publish retains its existing `contents: read`, `persist-credentials: false`,
   exact workflow SHA, tag, protected-environment, and token-free preflight
   gates.
4. Release-gate tests, workflow syntax, local workspace gates, independent
   review, PR CI, and exact merged-main CI pass on immutable heads.
