# WP-181 — CLI human `workflow list` pure formatter + tests

## Outcome

Human `vyane workflow list` goes through pure `format_workflow_list` used by
`print_workflow_list`. Unit tests drive the shipped formatter with real
`WorkflowJournalSummary` rows (status names + step-count totals).

## Motivation

WP-179/180 locked task list/status human paths. `workflow list` still used only
untestable `println!`s despite already projecting journal status and step
counts.

## Acceptance

1. `print_workflow_list` is a thin wrapper over `format_workflow_list`.
2. Formatter prints header columns id/started_at/name/status/steps and
   snake_case status via `workflow_status_name`.
3. Step line uses real `WorkflowStepCounts` totals (`success/total ok, failed,
   skipped, cancelled`).
4. Unit tests call the shipped formatter (not a re-implementation).
5. Local gates and independent review pass; no CI isolation train.
