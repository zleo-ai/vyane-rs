# WP-120 — multi-thread delayed MockServer timeout unit fixtures

## Outcome

Run delayed MockServer timeout unit fixtures in `daemon_client` and `vyane-quota`
on two-worker Tokio runtimes so client timers and mock delays stay independently
schedulable under suite load.

Production daemon client and quota HTTP reader behavior do not change.

## Motivation

WP-111–119 covered multi-mock, cancel, dual-path, and process-isolation paths.
Two remaining single-mock timeout fixtures still used the default current-thread
runtime with `set_delay`, where timer progress can starve under suite load.
Lease-sensitive restart/graceful-stop fixtures stay on the current-thread
runtime intentionally (WP-113).

## Acceptance

1. Named delayed timeout fixtures use two Tokio workers.
2. Existing assertions remain unchanged.
3. No production code changes.
4. Local targeted runs, gates, review, PR CI, and exact merged-main CI pass.
