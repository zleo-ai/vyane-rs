# WP-179 — CLI human `task list` surfaces failure_code

## Outcome

Human-mode `vyane task list` prints each row's durable `TaskRow.failure_code`
(snake_case) when present. Machine JSON already serializes the same optional
field on `TaskRow`; this package closes only the human table gap.

## Motivation

WP-178 closed the human gap for daemon workflow status failure codes.
Detached `task list` still projected `failure_code` into JSON rows and
`TaskRow::{from_record,from_legacy}`, but the human table only showed
id / state / duration / created / target — so operators could not scan
terminal failure classification without `--json`.

## Acceptance

1. Shipped human list path (`print_task_table` → `format_task_table`) prints
   the row's `failure_code` as a stable snake_case token when `Some`.
2. No-code tables invent no failure column or placeholder failure cells;
   prior columns remain present and readable.
3. Unit tests drive the shipped formatter (coded / no-code / mixed rows).
4. Local gates and independent review pass; no CI isolation train.
