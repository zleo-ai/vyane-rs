# WP-134 — multi-thread MockServer protocol client fixtures

## Outcome

Run MockServer-backed protocol client fixtures on a two-worker Tokio runtime so
wiremock-backed complete/stream/retry paths stay independently schedulable
under suite load.

Production protocol client behavior does not change.

## Motivation

Earlier WPs multi-threaded delayed and multi-mock protocol/authorized fixtures.
The remaining `protocol_clients` acceptance suite still used the default
current-thread runtime for every MockServer case.

## Acceptance

1. MockServer-backed `protocol_clients` fixtures use two Tokio workers.
2. Existing assertions remain unchanged.
3. No production code changes.
4. Local targeted runs, gates, review, PR CI, and exact merged-main CI pass.
