# WP-87 — Configurable native web fetch

## Outcome

Add a dedicated `web_fetch` tool to Vyane's native in-process AgentRun lane.
The tool remains absent unless a submission grants
`native_permissions.web_fetch`.

This is independent from hosted `web_search` and from command networking. It
is a Vyane-owned bounded HTTPS text client, not `curl`, a shell escape, a model
provider feature, or a new harness.

## Public policy

```json
{
  "native_permissions": {
    "web_fetch": {
      "allow_domains": ["docs.rs", "github.com"],
      "route": "environment_proxy",
      "max_fetches": 4,
      "max_response_bytes": 524288,
      "max_redirects": 3
    }
  }
}
```

- Omission means that `web_fetch` is neither advertised nor executable.
- `allow_domains` is required and non-empty. Entries are lowercase ASCII DNS
  names and include their subdomains.
- `route` is `direct` by default. `environment_proxy` explicitly uses
  `HTTPS_PROXY`; the client never silently falls back between the two.
- The first slice accepts only HTTPS on the default port, has no userinfo,
  cookies, credentials, custom headers, upload body, or arbitrary HTTP method.
- `max_fetches` limits tool invocations in one native run.
- `max_response_bytes` caps the decoded response body while it streams.
- `max_redirects` is bounded and every redirect remains inside the same frozen
  domain policy.
- Only declared UTF-8 text, JSON, XML, XHTML, RSS, and Atom responses are
  returned. Binary or undeclared content fails closed.

## Permission and network boundary

- Submission validates and freezes the complete policy in the private native
  spool. Earlier schema versions remain recoverable only when the newer
  capability is absent.
- The trusted tool validates the initial URL before network activity. The
  protocol client repeats domain validation before every redirect request.
- Each hostname is resolved before its physical request. Empty answers, IP
  literals, and loopback, private, link-local, multicast, documentation,
  benchmark, carrier-grade NAT, and other reserved IPv4/IPv6 ranges fail
  closed in direct mode.
- Direct mode pins the checked DNS addresses into the TLS client and disables
  process proxies. Environment-proxy mode accepts only public answers or the
  `198.18.0.0/15` Fake-IP range before sending the admitted hostname through
  an explicitly configured `HTTPS_PROXY`; other private answers still fail.
- Automatic redirects and implicit request retries are disabled. Live native
  authority is revalidated immediately before every physical request.
- Cancellation, a per-request timeout, and the native run deadline cover DNS,
  send, redirects, and response streaming.
- The final URL is rechecked before the result reaches the model. Returned
  bytes are labelled as untrusted web content and bounded again by the native
  tool-result limit.

The fetched page is untrusted input and may contain prompt injection. This
package limits where content can come from and what network effects the tool
can perform; it does not claim that page text is safe instructions.

## Explicit exclusions

- no HTTP or non-default HTTPS port;
- no arbitrary method, request body, credentials, cookies, custom headers, or
  binary download;
- no implicit route fallback or proxy other than explicit `HTTPS_PROXY`;
- no implicit command networking or hosted search;
- no browser rendering, JavaScript execution, authentication flow, or
  cross-page crawl;
- no approval resume, native session resume, or layered managed policy.
