# WP-107 — bound resident completion supervisor shutdown

## Outcome

Keep coverage fail-fast and deterministic by running the resident completion
supervisor fixture on a two-worker Tokio runtime and bounding its final
supervisor join with the same two-second test budget used by the adjacent
host-cancellation fixture.

Production supervisor, completion, cancellation, and timeout behavior do not
change.

## Failure evidence

PR #61 run `30513279322` at commit
`d416fdf15be2ed64f34e26e8ade2e3d883c4cfb3` passed Ubuntu, macOS, MSRV, and
release-gate. Coverage ran
`agent_supervisor::tests::resident_supervisor_publishes_committed_completion`
by exact name in a fresh process. The test remained active from
`04:15:52Z` until the 20-minute job timeout cancelled it.

The fixture already bounds its waits for execution entry and completion
publication at two seconds, but its final supervisor join after cancellation
was unbounded. It also drives concurrent execution and completion loops on
Tokio's default current-thread test runtime. A fresh process alone therefore
does not make the test fail-fast or guarantee independent loop progress.

## Acceptance

1. Execution and completion loops can progress on independent Tokio workers.
2. The final supervisor join succeeds within the existing two-second test
   budget or fails the exact test instead of consuming the whole CI job.
3. No production code, assertion, or timeout is widened.
4. Repeated exact normal and coverage runs, formatting, Clippy, MSRV, release
   gate, parity, independent review, PR CI, and exact merged-main CI pass on
   immutable heads.
