# WP-402 — Pure config check diagnostics on `vyane check`

## Outcome

`vyane check` logs pure kind lines from a successful static `check_config`
report (overall status, per-provider credential, per-profile status, issue
codes) and pure native permission-axis lines from the redacted permission
summary. Human stdout layout is unchanged.

## Motivation

WP-360 published pure diagnostics formatters without a CLI host. `vyane check`
already loads config and prints human permission ceilings; wiring pure kind
logs uses the existing static report without inventing hosts.

## Acceptance

1. On successful `check_config`, log pure `format_config_check_status_line` + `status = as_str`.
2. For each provider, log pure credential status line + `credential = as_str`.
3. For each profile, log pure profile-check status line + `status = as_str`.
4. For each report/profile issue, log pure config-issue code line + `code = as_str`.
5. `print_permission_check` logs pure native-axis lines for the six axes.
6. Clear `#[allow(dead_code)]` on the five pure formatters used here.
7. Human stdout and exit codes unchanged (`check_config` Err does not fail the CLI path).
8. Local gates and independent review pass.
