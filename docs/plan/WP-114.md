# WP-114 — multi-thread native_agent mocks and bound multi-lane completion cycles

## Outcome

1. Run Wiremock-backed unit tests in `native_agent.rs` on a two-worker Tokio
   runtime so multi-target failover, delayed wire, and cancellation fixtures
   stay independently schedulable under the serialized CLI suite.
2. Bound `multi_lane_shutdown_final_pass_publishes_late_completion_once` to
   accept one empty intermediate completion poll under suite load while still
   requiring exactly one late publication.

Production native AgentRun and supervisor behavior do not change.

## Failure evidence

PR #66 at `5d9ddf7` failed Ubuntu on
`multi_lane_shutdown_final_pass_publishes_late_completion_once` with
`exit.completion.cycles` equal to 3 instead of the hard-coded 2, while still
publishing late completion once. The assertion was timing-brittle under suite
load, not a double-publish regression.

## Acceptance

1. Every `native_agent` unit test that constructs a `MockServer` uses two
   Tokio workers.
2. Multi-lane shutdown still publishes late completion once and bounds cycles
   without requiring a single exact intermediate count under load.
3. Local unit/suite runs, gates, review, PR CI, and exact merged-main CI pass.
