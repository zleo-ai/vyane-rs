# WP-85 — Configurable command networking

## Outcome

Native `run_command` remains networkless by default. A submission may add a
separate `native_permissions.command_network` policy that grants bounded HTTPS
CONNECT access to exact DNS names or wildcard subdomains and explicit ports.

This extends Vyane's native in-process agent lane. It is not a second harness
and it does not change the existing Codex or Claude Code process adapters.

## Public policy

```json
{
  "native_permissions": {
    "command_execution": {
      "allow": [
        { "program": "cargo", "args_prefix": ["fetch"] }
      ],
      "max_seconds": 120
    },
    "command_network": {
      "allow": [
        { "host": "crates.io", "ports": [443] },
        { "host": "*.github.com", "ports": [443] }
      ],
      "route": "direct",
      "max_connections": 8,
      "max_bytes": 67108864,
      "connect_timeout_seconds": 10
    }
  }
}
```

`command_network` is invalid without `command_execution`. Omission preserves
the existing networkless behavior. Host patterns are lowercase ASCII DNS names;
IP literals, top-level wildcards, malformed labels, private/reserved addresses,
and mixed public/private DNS answers are rejected.

`route` defaults to `direct`. `environment_proxy` uses the host's credential-free
HTTP `HTTPS_PROXY` as a trusted egress boundary, which is useful on hosts using
Fake-IP DNS. The proxy address is never injected into the untrusted command.

## Enforcement boundary

- Bubblewrap keeps `--unshare-net`; the command never shares the host network.
- A trusted proxy listens only on `127.0.0.1:3128` inside that isolated network
  namespace.
- The proxy talks over inherited descriptor 5 to a Rust broker outside the
  namespace. The untrusted command child does not inherit that descriptor.
- The broker rechecks live native authority for every connection, resolves DNS,
  rejects non-public answers, opens the exact resolved address, requires the
  TLS ClientHello SNI to match the CONNECT host, and enforces aggregate
  connection and byte limits.
- Network-enabled seccomp permits only IPv4/IPv6 sockets. Unix sockets,
  socketpairs, packet sockets, VSOCK, keyrings, shared-memory allocation and the
  other command-profile denials remain blocked.
- Credentials are not injected and TLS is not intercepted.

The first slice supports HTTPS CONNECT sequentially. Plain HTTP proxying and
parallel tunnels are intentionally outside this work package.

## Verification

- Closed policy JSON and frozen spool schema round-trip.
- Legacy schema 5 inputs remain valid only when `command_network` is absent.
- Network policy is rejected without command execution.
- Exact/wildcard host and port matching tests.
- Private, reserved, documentation and mapped loopback IP rejection tests.
- Sandbox test proving only the loopback proxy is reachable.
- Sandbox test proving direct Internet connections remain unreachable.
- Live authority revocation immediately before broker connection blocks it.
- Existing networkless command confinement suite remains green.
