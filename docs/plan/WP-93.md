# WP-93 — configurable CLI-harness permission ceilings

## 目标

为 Claude Code / Codex CLI harness 的现有 `read-only` / `write` / `full`
语义增加可配置、单调收紧的执行上限，同时保留各 adapter 对 vendor CLI
参数的封闭映射。

本包不把 vendor-specific 原始 flags 暴露给请求，不增加工具，也不实现
approval resume。

## 决策模型

- 请求中的 `sandbox` 仍表示任务所需权限；省略时仍为 `read-only`。
- 每个 user、project、explicit 与 managed 配置层可独立贡献一个
  `[harness_permissions] max_sandbox` 上限。
- 所有上限取最严格值；高优先级配置不能擦除或放宽低层限制。
- 请求超过任一上限时，在 durable task/run、executor construction、model wire
  或 subprocess spawn 前 fail closed；不静默降级后继续执行。
- 上限约束包含任一 CLI-harness leg 的整条 failover chain。direct HTTP 与
  Native/Canto lane 不借此获得 workspace 权限。
- `Sandbox` 到 Codex CLI / Claude Code 参数的映射仍由受信 adapter 固定实现；
  配置不能注入任意 argv、permission mode 或 tool rule。

## 验收门

1. user/project/explicit/managed 层分别可贡献上限，组合只会收紧。
2. `read-only <= write <= full` 的闭合顺序由 typed helper 固定，不依赖 enum
   声明顺序。
3. 超限的 fresh、detached、REST、workflow 与 failover CLI-harness dispatch
   在任何持久化或 spawn 前被拒绝。
4. 精确等于上限和更窄请求仍保持现有 Codex / Claude adapter argv。
5. direct HTTP 与 Native/Canto 权限路径行为不变。
6. 运行全仓 format、Clippy、test，并通过独立评审与云端 CI。

## 需要 Grill 的后续边界

`ask` 的 owner-scoped approval store、过期、一次性消费、policy/workdir drift、
checkpoint 与 exact resume 语义仍需 Grill/Eosphor 对齐；WP-93 不自行定义。
