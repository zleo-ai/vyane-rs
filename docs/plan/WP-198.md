# WP-198 — Extract daemon workflow view pure formatter into output.rs

## Outcome

Human daemon `workflow status` / submit projection moves to public
`format_daemon_workflow_view` / `print_daemon_workflow_view` in `output.rs`
alongside the other pure human formatters. Existing unit tests migrate with the
shipped path (WP-152 output + WP-178 failure_code behavior unchanged).

## Motivation

After WP-179–197, the daemon workflow human view was the last pure multi-line
formatter still private to `command.rs`. Extracting keeps one human-output
module and the same shipped function under test.

## Acceptance

1. `print_daemon_workflow_view` / `format_daemon_workflow_view` live in
   `output.rs`; command paths call `crate::output::print_daemon_workflow_view`.
2. Behavior preserved: state line, optional failure, journal counts, output /
   output omitted.
3. Unit tests call the shipped `output` formatter with real `WorkflowTaskView`
   values (bounded output, omitted, non-success hide, failure codes).
4. No private duplicate formatter remains in `command.rs`.
5. Local gates and independent review pass; no CI isolation train.
