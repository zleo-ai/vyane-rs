# WP-400 — Goal human tab/status columns use as_str kind tokens

## Outcome

CLI goal human projections that previously formatted closed status/kind enums
via Display now call `as_str()` explicitly (kind-only token path, matching
WP-397 takeover approval columns).

## Motivation

Display is currently delegated to `as_str`, but human columns should not
depend on that coincidence. Explicit `as_str` matches the pure-token contract
and keeps operators/parsers on stable snake_case tokens.

## Acceptance

1. `format_goal_line` status column uses `goal.status.as_str()`.
2. `format_progress_event_line` and `format_goal_event_line` kind columns use `event.kind.as_str()`.
3. `format_pursue_outcome` status field uses `outcome.status.as_str()`.
4. Existing human-format unit tests still pass (token text unchanged).
5. Local gates and independent review pass.
