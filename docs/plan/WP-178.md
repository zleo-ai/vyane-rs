# WP-178 — CLI human daemon workflow status surfaces failure_code

## Outcome

Human-mode `vyane workflow status` / submit responses print the durable
`failure_code` already present on `WorkflowTaskView.task` (and projected by MCP
as `WorkflowView.failure_code`). Machine JSON continues to serialize the same
field on the task record.

## Motivation

WP-177 closed the human gap for WP-152 success `output`. Failed, timed-out,
cancelled, and interrupted daemon workflows still only printed id and state in
human mode, so operators could not see the bounded failure classification
without switching to `--json` or MCP — even though `task status` and the MCP
lifecycle view already exposed it.

## Acceptance

1. Human formatter prints `failure <snake_case_code>` when
   `WorkflowTaskView.task.failure_code` is set.
2. Human formatter invents no failure line when the code is absent.
3. WP-177 output / output-omitted lines remain unchanged.
4. Unit tests drive the shipped formatter with real `WorkflowTaskView` values.
5. Local gates and independent review pass; no CI isolation train.
