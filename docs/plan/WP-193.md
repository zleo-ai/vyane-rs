# WP-193 — CLI human permission-check pure formatter + tests

## Outcome

Human `vyane check` prints the redacted permission summary through pure
`format_permission_check` / `print_permission_check` over
`vyane_service::PermissionCheck` (CLI-harness max sandbox + native axis
statuses and tool-policy counts).

## Motivation

The native permission ceiling surface is a P1 half-landed operator seam:
`check_permissions` already freezes a redacted summary, but the human CLI
printed it via ad-hoc `println!` with private helpers and no unit coverage.

## Acceptance

1. `vyane check` human permissions block uses `print_permission_check` →
   `format_permission_check` (layout preserved).
2. Harness line shows `max_sandbox` token (`read-only`/`write`/`full`) and
   `ceiling_layers`.
3. Native line shows axis tokens (`unrestricted_by_config`/`bounded`/`disabled`)
   plus tool_policy_layers and tool_policy_rules.
4. Unit tests drive the shipped formatter with real `PermissionCheck` values.
5. Local gates and independent review pass; no CI isolation train.
