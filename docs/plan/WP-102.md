# WP-102 — make pursuit timeout fixture test one clock boundary

## Outcome

Keep the pursuit overall-timeout test focused on proving that one segment starts
and receives only the remaining total budget.

Production pursuit behavior and timeout defaults do not change.

## Failure evidence

The fixture spawned a real `cmd:false` acceptance verifier inside a 200
millisecond overall pursuit budget. Under Linux CI load, verification consumed
that complete budget before the fake runtime started, so the pursuer correctly
reported zero started segments while the test required exactly one.

The fixture now allows 1.5 seconds for a verifier bounded to one second plus
pursuit, while the lease renewal's whole-second rounding still keeps the lease
past that overall deadline. It sets the nominal segment timeout to five seconds
and still proves that the runtime starts once and receives a timeout shortened
to the remaining overall budget.

## Acceptance

1. The runtime starts exactly once after real unsatisfied verification.
2. The captured segment timeout is no greater than the overall budget and
   remains below the nominal segment timeout.
3. The pursuit still pauses for the overall-timeout reason without starting a
   second segment.
4. Repeated exact tests, workspace gates, parity, independent review, and cloud
   CI pass on the exact committed head.
