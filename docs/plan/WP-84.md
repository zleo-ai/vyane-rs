# WP-84 · Configurable native command execution

## Outcome

Add the first bounded command tool to the fresh, sessionless native lane
without turning `Sandbox::Full` or filesystem write permission into an
implicit shell grant.

The tool is a structured `run_command(program, args)` operation. A native
submission must opt in with a frozen command policy containing explicit
program and argument-prefix rules. Omission means that no command tool is
advertised or executable.

## Permission shape

```json
{
  "native_permissions": {
    "command_execution": {
      "allow": [
        { "program": "git", "args_prefix": ["status"] },
        { "program": "cargo", "args_prefix": ["test"] }
      ],
      "max_seconds": 120
    }
  }
}
```

- Program names are basenames, never paths.
- Arguments are passed directly to the program. There is no shell parsing,
  interpolation, pipeline, redirection or command substitution.
- A rule matches one exact program and an exact argument prefix. The remaining
  arguments are still bounded but may vary.
- The first process sandbox mounts the complete admitted workspace read-only.
  A submission with `filesystem_read.exclude` entries is therefore rejected
  instead of letting a command bypass those exclusions.
- Empty allowlists, invalid names, oversized rules and unbounded timeouts fail
  before the first model request.
- The frozen policy is covered by the native policy digest.

Future user, project and managed layers may compose the same shape. Managed
denies and limits remain non-overridable floors; this package does not invent a
second global configuration system.

## Host boundary

The first command slice is Linux-only and read-only:

- The host must provide `/usr/bin/bwrap`; submission probes the exact profile
  and fails before a model request when it is missing or unusable.
- Bubblewrap constructs a fresh mount, PID, IPC, UTS and network namespace.
- The exact admitted `PinnedWorkdir` is descriptor-bound into `/workspace`
  read-only. Its serialized path is not reopened as authority.
- Only fixed runtime directories needed to launch ordinary system programs are
  mounted read-only. The child receives a private temporary directory and a
  small explicit environment.
- Network is unavailable even if the outer sandbox is `Full`.
- Command output, argument count, argument bytes and duration are bounded.
- Cancellation, timeout, normal exit and future drop use the existing
  process-group cleanup path so descendants cannot outlive the tool call.
- Live native authority is checked at registry dispatch and again immediately
  before the physical child spawn.

This package intentionally does not grant command-side workspace writes.
Filesystem mutation continues through the confined `write_file` and
`edit_file` tools. A later package may add a separately configured writable
command profile after it can enforce protected paths and exclusions below the
process.

The tool itself never parses shell syntax. A shell or interpreter is available
only if its exact program and argument prefix are explicitly admitted, and it
still runs inside the same read-only, networkless process sandbox.

## Separate network axes

Command network and web search remain different capabilities:

- `command_execution` decides which local programs may run.
- a later `command_network` policy decides which destinations those child
  processes may reach;
- a later `web_search` policy controls a dedicated search/fetch tool without
  granting arbitrary child-process network access.

The three switches are independently configurable and default to disabled.

## Verification gate

- Policy validation and digest round trips cover exact allow rules and limits.
- Tool tests cover rule matching, malformed calls, output bounds, non-zero
  exits, timeout, cancellation and descendant cleanup.
- Linux adversarial tests prove that the command cannot write the workspace,
  read an unmounted host path, or reach loopback/public network destinations.
- Submission probes the exact Bubblewrap and descriptor-bound workspace
  profile before any paid model request.
- A resident acceptance test proves HTTP submission → model tool call →
  sandboxed command → durable completion.
- Non-Linux hosts fail closed.
- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- The exact PR head receives independent cross-model review and all required
  GitHub checks before merge.
