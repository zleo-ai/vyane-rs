# WP-111 — keep native web-search mocks independently schedulable

## Outcome

Run `native_web_search_uses_the_separate_frozen_responses_target` on a
two-worker Tokio runtime so its dual Wiremock targets (chat completions and
hosted search responses) and control-plane status polling can make independent
progress after earlier acceptance fixtures in the same process.

Production daemon, native search, and timeout behavior do not change.

## Failure evidence

Main run `30518689607` at merge commit
`81254fae05258ecec7e95d3bbbac3dd3b8a4ee5b` passed release-gate, MSRV, macOS,
and coverage. Ubuntu failed
`native_web_search_uses_the_separate_frozen_responses_target` with
`AgentRun status request exceeded its polling budget` after ~96 seconds in the
serialized `daemon_agent_acceptance` binary. The daemon log contained only the
listen line, so the resident lane never reached a terminal state while the
fixture waited.

The same PR head had passed Ubuntu. The fixture drives two Wiremock servers
plus daemon status polling on Tokio's default current-thread test runtime.
That matches the earlier dual-target scheduling handoffs addressed by WP-108
for the mixed-lane fixture. A two-worker test runtime preserves the intended
concurrency without widening production budgets.

## Acceptance

1. The fixture uses an explicit two-worker Tokio runtime.
2. Existing terminal budget and assertions remain unchanged.
3. No production code or CI process-boundary changes unless still required.
4. Local exact and full-binary runs, gates, review, PR CI, and exact
   merged-main CI pass.
