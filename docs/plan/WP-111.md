# WP-111 — keep multi-mock native AgentRun fixtures independently schedulable

## Outcome

Run the dual/multi Wiremock native AgentRun acceptance fixtures on a
two-worker Tokio runtime so chat, failover, and hosted-search targets stay
independently schedulable while control-plane status polling runs after earlier
acceptance fixtures in the same process.

Covered fixtures:

- `native_web_search_uses_the_separate_frozen_responses_target`
- `native_agent_submit_fails_over_and_exact_retry_rejects_chain_drift`

Production daemon, native search, failover, and timeout behavior do not change.

## Failure evidence

Main run `30518689607` at merge commit
`81254fae05258ecec7e95d3bbbac3dd3b8a4ee5b` passed release-gate, MSRV, macOS,
and coverage. Ubuntu failed
`native_web_search_uses_the_separate_frozen_responses_target` with
`AgentRun status request exceeded its polling budget`. The daemon log contained
only the listen line.

PR #63 head then passed Ubuntu after giving the web-search fixture two workers,
but coverage failed
`native_agent_submit_fails_over_and_exact_retry_rejects_chain_drift` with the
same polling-budget / listen-only pattern under llvm-cov. That fixture drives
primary and secondary Wiremock targets through failover plus status polling on
the default current-thread test runtime.

Both cases match the dual-target scheduling handoffs addressed by WP-108. A
two-worker test runtime preserves the intended concurrency without widening
production budgets.

## Acceptance

1. Both multi-mock fixtures use an explicit two-worker Tokio runtime.
2. Existing terminal budgets and assertions remain unchanged.
3. No production code or CI process-boundary changes unless still required.
4. Local exact and full-binary runs, gates, review, PR CI, and exact
   merged-main CI pass.
