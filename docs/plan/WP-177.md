# WP-177 — CLI human daemon workflow status surfaces WP-152 output

## Outcome

Human-mode `vyane workflow status` / submit responses print the bounded success
`output` (or `output omitted`) already projected onto `WorkflowTaskView` by
WP-152. Machine JSON continues to serialize the same fields.

## Motivation

WP-152 added redacted, size-bounded answer projection on the durable workflow
lifecycle view for MCP and JSON. The CLI human printer only showed id, state,
and journal counts, so operators using default (non-`--json`) status could not
see the projected answer even when the daemon had loaded it.

## Acceptance

1. Human formatter prints `output` + body when `WorkflowTaskView.output` is set.
2. Human formatter prints `output omitted` when `output_omitted` is true and no body.
3. Non-success views do not invent output lines.
4. Unit tests drive the shipped formatter with real `WorkflowTaskView` values.
5. Local gates and independent review pass; no CI isolation train.
