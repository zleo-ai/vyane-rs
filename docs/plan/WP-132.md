# WP-132 — bound pursuit cancel wall-clock check for loaded CI

## Outcome

Keep
`overall_timeout_and_cancellation_pause_without_another_segment`'s cooperative
cancel wall-clock assertion tight enough to catch a stuck pursue path, while
allowing loaded CI runners (notably macOS suite handoff) to finish a healthy
cancel within two seconds.

Production overall-timeout and cancel semantics do not change.

## Failure evidence

Main `5974642` attempt (WP-131) macOS failed this fixture with
`assertion failed: started.elapsed() < Duration::from_secs(1)` inside the
serialized goal pursuit suite. A failed-job re-run then passed. The body is a
wall-clock liveness check, not a production budget.

## Acceptance

1. Cancel wall-clock assertion uses a two-second upper bound.
2. Status/reason/segment assertions remain unchanged.
3. No production code changes.
4. Local gates, review, PR CI, and exact merged-main CI pass.
