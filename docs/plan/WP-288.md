# WP-288 — Log all OwnerContextError construction kinds

## Outcome

`OwnerContext::from_authenticated` and principal minting paths log closed
`OwnerContextError` kinds (`invalid_principal`, `resolution_failed`,
`invalid_owner`, `reserved_owner`) on failure, parallel to WP-287
authentication logging.

## Motivation

WP-287 only logged authentication failure. Resolution/reserved/invalid owner
paths still return silently without a kind diagnostic.

## Acceptance

1. `AuthenticatedPrincipal::new` failure path logs `invalid_principal`.
2. `from_authenticated` logs `resolution_failed` / `invalid_owner` /
   `reserved_owner` as appropriate (kind only).
3. No principal subject or credential appears in log fields.
4. Local gates and independent review pass.
