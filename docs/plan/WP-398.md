# WP-398 — Pure PursuitCheckpointStatus on goal get projection

## Outcome

Goal CLI `get` loads the durable pursuit checkpoint for both JSON and human
paths and, when present, logs pure `format_pursuit_checkpoint_status_line` with
structured `status = as_str`.

## Motivation

WP-358 published pure checkpoint status lines. Goal detail JSON already
projects `pursuit_checkpoint.status`, but the get path never emitted the pure
kind diagnostic and the human branch skipped loading the checkpoint entirely.

## Acceptance

1. `get` loads `pursuit_checkpoint` for JSON and human paths.
2. When a checkpoint is present, log pure checkpoint-status line + `status = as_str`.
3. Clear `#[allow(dead_code)]` on `format_pursuit_checkpoint_status_line`.
4. Human event rows and JSON body shape remain unchanged (only add pure log).
5. Local gates and independent review pass.
