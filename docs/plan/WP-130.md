# WP-130 — multi-thread remaining MockServer CLI acceptance fixtures

## Outcome

Run the remaining MockServer-backed CLI acceptance fixtures on a two-worker
Tokio runtime so wiremock-backed dispatch, workflow, stream, and review paths
stay independently schedulable under suite load.

Production CLI dispatch behavior does not change.

## Motivation

WP-115 multi-threaded multi-mock failover CLI fixtures. Many other
MockServer-backed CLI acceptance cases still used the default current-thread
runtime (dispatch ledger/auto-route/labels, workflow suite, streaming, and
review pipeline).

Harness-only and pure-config route fixtures stay on the default current-thread
runtime.

## Acceptance

1. Named remaining MockServer CLI acceptance fixtures use two Tokio workers.
2. Existing assertions remain unchanged.
3. No production code changes.
4. Local targeted runs, gates, review, PR CI, and exact merged-main CI pass.
