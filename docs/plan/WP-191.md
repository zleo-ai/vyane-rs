# WP-191 — CLI human takeover approval line pure formatter + tests

## Outcome

Human continuity queue/decide (and other `print_takeover_result` paths) project
approval identity through pure `format_takeover_approval_line`: terminal-safe
approval_id / goal_id / step_id plus status Display snake_case.

## Motivation

Queue/decide human output was a two-column `println!` without terminal safety
or goal/step context. Operators debugging continuity handoffs need goal_id and
step_id next to the approval without opening JSON.

## Acceptance

1. Human `print_takeover_result` and `continuity_execute` settlement both use
   `format_takeover_approval_line` (JSON paths unchanged).
2. Line is tab-separated: safe approval_id, status snake_case, safe goal_id,
   safe step_id.
3. Status uses domain `Display` (`pending`, `in_flight`, …).
4. Unit tests drive the shipped formatter with real `TakeoverApprovalStatus`
   values (control-char escape + exact layout).
5. Local gates and independent review pass; no CI isolation train.
