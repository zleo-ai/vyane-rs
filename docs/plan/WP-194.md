# WP-194 — CLI human pursue outcome pure formatter + tests

## Outcome

Human `vyane goal pursue` projects `PursuitOutcome` through pure
`format_pursue_outcome`: snake_case status Display, terminal-safe goal id /
summary / optional distinct reason, and segment counters.

## Motivation

Pursue human mode only printed a terminal-safe summary line, omitting the
durable status and segment counters operators need when a pursuit pauses or
stops. Domain `PursuitStatus` lacked `as_str`/`Display` aligned with serde.

## Acceptance

1. Human pursue path uses `format_pursue_outcome` (JSON unchanged).
2. Always prints status (snake_case), goal, segments
   (started/completed/failures), summary; reason only when non-empty and not
   equal to summary; free text terminal-safe.
3. `PursuitStatus` has domain `as_str`/`Display`.
4. Unit tests drive the shipped formatter with real `PursuitOutcome` values.
5. Local gates and independent review pass; no CI isolation train.
