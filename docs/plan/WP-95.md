# WP-95 — retry transient daemon readiness lock contention

## 目标

避免 `vyane daemon start` 在新 daemon 已经成功启动、但控制代际正短暂发布
时，因为一次 500 ms 控制锁竞争而误判启动失败并杀掉健康进程。

本包不放宽启动前的现存 daemon 检查，不增加控制锁预算，也不改变控制文件
的所有权、原子发布或认证语义。

## 决策模型

- daemon 控制锁的单次等待预算仍为 500 ms。
- 控制锁超时使用内部类型标识，不依赖错误字符串判断。
- 启动前读取现存控制代际时，锁超时仍立即失败，避免覆盖状态不明的 daemon。
- 子进程拉起后的就绪轮询只把该类型化锁超时视为“尚未就绪”，继续受既有
  30 秒总启动预算约束。
- 权限、路径类型、控制 JSON、token 和其他 I/O 错误仍立即失败。

## 验收门

1. 启动就绪读取遇到类型化控制锁超时时返回“尚未就绪”，锁释放后能读取
   已发布的控制代际。
2. token 等非锁错误在启动就绪读取中仍立即返回。
3. daemon restart 接受测试定向重复运行通过。
4. 运行全仓 format、Clippy、test，并通过独立评审与云端 CI。
