# WP-105 — isolate the service resident-broker lifecycle fixture

## Outcome

Keep the macOS main test gate bounded by giving the service-owned, no-delivery
lane resident broker fixture a fresh Tokio runtime and test process.

Production service, broker, message, permission, and checkout behavior do not
change.

## Failure evidence

Main run `30509521653` at merge commit
`20f4dd879ffd01dbff21a4c1d6c83ecc704ddd4e` completed checkout v6, Ubuntu,
coverage, MSRV, and release-gate successfully. Its macOS job reached the
serialized 207-test `vyane-service` batch and completed
`message::tests::process_style_completion_prepares_and_stages_exact_message`.
The next test,
`message::tests::resident_broker_assembly_owns_scope_and_drains_without_delivery_lanes`,
never completed; Actions cancelled the process at the 20-minute job limit.

The same exact source passed the fixture in the PR run. The fixture assembles a
resident broker with no delivery lanes, owns a short-lived Tokio cancellation
runtime, and is stable in a fresh process. This is the same bounded
test-process handoff class already isolated for other supervisor fixtures.

## Acceptance

1. Normal service tests remain serialized and skip only the two observed
   lifecycle fixtures that are immediately run by exact name in separate
   processes.
2. Coverage measures the same complete service test set with the same process
   boundaries.
3. No test is ignored and no assertion or production timeout is widened.
4. Local exact split commands, formatting, Clippy, MSRV, release gate, parity,
   independent review, PR CI, and exact merged-main CI pass on immutable heads.
