# WP-205 — Pure approval-required tool output (native ask surface)

## Outcome

When a native tool decision is `ask`, the model-facing stop message is produced
by pure `approval_required_output` / `missing_approval_plan_output` used on the
shipped prepare path. Plan hash prefixes never panic on short digests.

## Motivation

The P1 ask surface already terminates without execution, but the ERROR strings
were inline and used a slicing form (`[..12]`) that assumes a long hash. Pure
helpers make the operator/model contract unit-testable and safer.

## Acceptance

1. Ask branch with approval uses `approval_required_output(tool, plan_hash)`.
2. Ask branch without approval plan uses `missing_approval_plan_output()`.
3. Plan prefix is 12 ASCII chars when available; shorter hashes print fully
   without panic.
4. Unit tests drive the shipped pure helpers; existing ask integration tests
   remain green.
5. Local gates and independent review pass; no CI isolation train.
