# WP-128 — isolate restart settlement fixtures in CI

## Outcome

Run these restart fixtures in a fresh CI process:

1. `restart_settles_expired_native_controller_without_replaying_private_input`
   (normal + coverage jobs)
2. `restart_recovers_exact_controller_without_replay` (normal job; coverage
   already isolated this fixture)

Production restart settlement and no-replay guarantees do not change. Both
fixtures stay on the intentional current-thread Tokio runtime.

  `restart_settles_expired_...` with `left: "running"` / `right: "timed_out"`
  after suite neighbors; three solo re-runs passed (~4s each).

  `restart_recovers_exact_controller_without_replay` with
  `assertion failed: Instant::now() < deadline` inside the serialized suite
  after neighboring restart fixtures were skipped. Coverage still passed
  because that job already isolated the recovery fixture.

## Acceptance

1. Normal and coverage jobs skip `restart_settles_expired_...` in the
   serialized CLI suite and re-run it alone via `--exact`.
2. Normal job also skips and exact-runs `restart_recovers_...` (coverage
   already did).
3. No production code or assertion changes; runtime flavor remains current-thread.
4. Local gates, review, PR CI, and exact merged-main CI pass.
