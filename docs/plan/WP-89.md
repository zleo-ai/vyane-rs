# WP-89 — rmcp 3.0 and Rust 1.88 baseline

## Outcome

Move Vyane's MCP server and real-protocol tests from `rmcp` 0.5 to the stable
3.0 SDK instead of retaining an obsolete pre-1.0 protocol dependency.

The workspace MSRV moves from Rust 1.85 to Rust 1.88 at the same boundary.
`rmcp` 3.0 declares Rust 1.88, and the macro chain used by recent 1.x and 2.x
releases also requires Rust 1.88. There is no honest intermediate upgrade that
preserves the old MSRV.

## Compatibility decision

This repository is still an explicitly unstable pre-release. No workspace
crate or GitHub release has been published, so the Rust 1.85 CI floor is not an
existing registry-consumer contract. Raising the floor before the first public
package release is preferable to publishing on the already-obsolete SDK and
breaking compatibility immediately afterwards.

The change does not add MCP tools or alter Vyane's owner, credential, workflow,
or execution authority boundaries.

## Migration

- replace removed or renamed rmcp model types with their 3.0 equivalents;
- use public schema helpers and wrapper paths rather than old internal aliases;
- construct non-exhaustive SDK models through their public builders;
- retain the exact nine-tool surface and bounded response behavior;
- keep real rmcp duplex tests and the CLI-to-MCP-to-authenticated-daemon
  acceptance as the behavioral gate;
- apply the mechanical `collapsible_if` cleanups exposed by the Rust 1.88
  let-chain baseline instead of suppressing the workspace lint;
- run the exact workspace against Rust 1.88 in CI.

## Verification

- `cargo +1.88.0 check --workspace --all-targets --locked`
- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- the exact PR head receives independent cross-model review and every required
  GitHub check before merge.

## Current implementation status

The dependency lock, API migration, real MCP transport tests, daemon
acceptance, workspace test suite, and exact Rust 1.88 check pass locally. The
work remains isolated until independent review and every required cloud check
pass on one exact committed head.
