# WP-127 — isolate shared-resident native submit fixture in CI

## Outcome

Run `native_agent_submit_uses_the_shared_resident_lane` in a fresh CI process
for normal and coverage jobs, alongside the process-agent, mixed-lanes,
native-writable, and native-command-permission isolations.

Production native AgentRun submit/output behavior does not change.

## Failure evidence

Local `cargo test --workspace` failed this fixture with
`reqwest::Error { kind: Request, url: .../v1/agent-runs/.../output, source: TimedOut }`
after the run had already reached a terminal path under suite load. A solo
re-run completed in ~1.5s. The body is stable alone; suite handoff after earlier
multi-thread daemon fixtures can leave output HTTP unresponsive.

## Acceptance

1. Normal and coverage jobs skip the fixture in the serialized CLI suite.
2. Both jobs re-run it alone via `--exact` in a fresh process (before dual-path
   workflow isolation on the normal job; with the other daemon isolations under
   coverage).
3. No production code or assertion changes.
4. Local gates, review, PR CI, and exact merged-main CI pass.
