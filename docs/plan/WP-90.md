# WP-90 — Descriptor-bound writable command roots

## Outcome

Add a bounded writable command profile without turning `Sandbox::Write`,
`Sandbox::Full`, filesystem tool writes, or command execution into implicit
whole-workspace mutation authority.

The existing structured `run_command(program, args)` policy gains an optional
list of exact workspace-relative writable roots:

```json
{
  "native_permissions": {
    "command_execution": {
      "allow": [
        { "program": "cargo", "args_prefix": ["fmt"] }
      ],
      "writable_roots": ["crates", "Cargo.toml"],
      "max_seconds": 120
    }
  }
}
```

An omitted or empty `writable_roots` list preserves the WP-84 read-only
behavior. Each root must already exist as a regular file or directory. The
workspace root itself, noncanonical paths, symlinks, mount crossings, duplicate
roots, and case-insensitive matches for `.git`, `.vyane`, `.codex`, or
`.claude` control paths fail closed.

## Enforcement boundary

- The whole admitted `PinnedWorkdir` remains descriptor-bound and read-only in
  Bubblewrap.
- Every configured writable root is independently opened beneath that pinned
  directory with `openat2` beneath/no-symlink/no-mount resolution. Admission
  retains those exact handles through the resident spool handoff; execution
  never reopens the serialized root path.
- Before admission and again immediately before each physical spawn, every
  retained directory is recursively inspected through descriptor-relative
  `openat2`. Symlinks, nested mounts, special files, excessive depth/entry
  counts, and regular files with hard-link aliases fail closed.
- The retained handles are duplicated onto fixed private descriptors and
  overlaid with Bubblewrap `--bind-fd`. Replacing a configured path after
  admission therefore cannot redirect write authority to a different object.
- A writable directory authorizes its complete subtree. Paths outside the
  listed roots remain read-only, including repository metadata that was not
  explicitly granted.
- The outer `Sandbox` must be `Write` or `Full`. The command policy remains a
  separate explicit opt-in; `filesystem_write` continues to control only the
  trusted `write_file` and `edit_file` tools.
- Command program/argv rules, command-network policy, live authority checks,
  resource ceilings, cancellation, and descendant cleanup are unchanged. The
  seccomp floor additionally denies hard-link and mount-management syscalls so
  an admitted command cannot create a new alias or mount crossing.

Writable roots compose monotonically through the WP-88 config ceilings. A
requested root must equal or be beneath a root allowed by every configured
ceiling. Configuration can restrict roots but cannot grant command execution.

This package deliberately does not add whole-workspace writes, creation of a
new writable root, shell-string policy, interactive approval, approval resume,
or session resume.

## Recovery compatibility

The native spool schema advances to 9. Schema-8 and older inputs remain
recoverable only when command writable roots are empty. The frozen policy
digest covers the exact root list, so retry or recovery cannot acquire a new
write target.

## Verification gate

- Policy tests cover canonical roots, protected control components,
  duplicates, ceiling subset checks, and the outer sandbox.
- Linux adversarial tests prove an allowlisted command can modify the exact
  descriptor-bound root but cannot create a sibling root-level file or mutate
  unlisted repository metadata. They also cover hard-link rejection and
  retained-handle behavior after path replacement.
- Host admission probes the same writable-root mount profile before a model
  request.
- Spool tests cover schema-8 compatibility and policy-digest binding.
- Existing command, network, filesystem, daemon, and resident acceptance tests
  remain green.
- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- The exact PR head receives independent real-model review and every required
  GitHub check before merge.
