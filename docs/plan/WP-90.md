# WP-90 — Descriptor-bound writable command roots

## Outcome

Add a bounded writable command profile without turning `Sandbox::Write`,
`Sandbox::Full`, filesystem tool writes, or command execution into implicit
whole-workspace mutation authority.

The existing structured `run_command(program, args)` policy gains an optional
list of exact workspace-relative writable roots:

```json
{
  "native_permissions": {
    "command_execution": {
      "allow": [
        { "program": "cargo", "args_prefix": ["fmt"] }
      ],
      "writable_roots": ["crates", "generated"],
      "max_seconds": 120
    }
  }
}
```

An omitted or empty `writable_roots` list preserves the WP-84 read-only
behavior. Each root must already exist as a directory. Regular-file roots are
rejected because a bind-mounted file cannot support atomic replacement by
editors and formatters. The workspace root itself, noncanonical paths,
symlinks, mount crossings, duplicate roots, and case-insensitive matches for
`.git`, `.vyane`, `.codex`, or `.claude` control paths fail closed.

Non-empty writable roots require a Bubblewrap build whose `--help` advertises
`--bind-fd FD DEST`. The Ubuntu 24.04 security-updated package provides this
capability; an unpatched base package without it remains usable for WP-84
read-only commands but fails WP-90 admission. CI asserts the capability after
installing the distro package instead of inferring support from a version
number.

## Enforcement boundary

- The whole admitted `PinnedWorkdir` remains descriptor-bound and read-only in
  Bubblewrap.
- Every configured writable root is independently opened beneath that pinned
  directory with `openat2` beneath/no-symlink/no-mount resolution. Admission
  retains those exact handles through the resident spool handoff; execution
  never reopens the serialized root path.
- Before admission and again immediately before each physical spawn, every
  retained directory is recursively inspected through descriptor-relative
  `openat2`. Symlinks, nested mounts, special files, excessive depth/entry
  counts, and regular files with hard-link aliases fail closed. Recursive
  inspection walks depth-first so a wide directory cannot retain one
  descriptor per sibling. It runs on Tokio's blocking pool; tool cancellation
  and deadlines remain responsive, while native settlement waits for the
  detached blocking work to become quiescent.
- The retained handles are duplicated onto fixed private descriptors and
  overlaid with Bubblewrap `--bind-fd`. Replacing a configured path after
  admission therefore cannot redirect write authority to a different object.
  Each mount set also records its source `WorkdirIdentity`; probes, spool
  installation, and tool spawn reject composition with a different pinned
  workspace even when the relative root strings match.
- All pending native handoffs share a 256-handle retention budget, including
  each pinned workdir and writable-root descriptor. This leaves headroom below
  a common 1024-descriptor process limit for SQLite, model sockets, probes, and
  transient spawn duplicates.
- A writable directory authorizes its complete subtree. Paths outside the
  listed roots remain read-only, including repository metadata that was not
  explicitly granted.
- The outer `Sandbox` must be `Write` or `Full`. The command policy remains a
  separate explicit opt-in; `filesystem_write` continues to control only the
  trusted `write_file` and `edit_file` tools.
- Command program/argv rules, command-network policy, live authority checks,
  resource ceilings, cancellation, and descendant cleanup are unchanged. The
  seccomp floor additionally denies hard-link and mount-management syscalls so
  an admitted command cannot create a new alias or mount crossing.
- Admission creates and removes a private marker directory inside every root,
  proving actual mutation capability before a paid model request. Read-only
  filesystems and roots that the sandbox identity cannot mutate fail closed.
- The local same-OS-user host is the authority boundary: another process with
  that user's direct workspace access is not treated as a sandbox adversary.
  Concurrent admitted commands cannot add hard links or mounts because the
  seccomp floor denies those syscalls; symlinks they can create still resolve
  against the read-only workspace mount.

Writable roots compose monotonically through the WP-88 config ceilings. A
requested root must equal or be beneath a root allowed by every configured
ceiling. Configuration can restrict roots but cannot grant command execution.

This package deliberately does not add whole-workspace writes, creation of a
new writable root, shell-string policy, interactive approval, approval resume,
or session resume.

Writable-root permission is storage authority over the complete named
subtrees, not a disk-quota service. `RLIMIT_FSIZE` bounds each file, and the
command retains time, process, memory, and descriptor ceilings, but an
allowlisted command may create many files within those limits. Operators must
not grant writable roots to commands they do not trust with the backing
filesystem's free space. A future copy/writeback or quota-backed execution
package is required before this permission can safely be offered to
adversarial commands.

## Recovery compatibility

The native spool schema advances to 9. Schema-8 and older inputs remain
recoverable only when command writable roots are empty. The frozen policy
digest covers the exact root list, so retry or recovery cannot acquire a new
write target. A schema-9 spool orphan with non-empty command writable roots
cannot install newly opened handles after a daemon restart; without the
original process-local descriptors, resubmission fails closed rather than
binding a replacement object at the same path.

Exact retries check durable AgentRun truth before opening or auditing writable
roots. A completed run therefore remains idempotently readable even when its
formerly writable tree has since changed; a new run still receives the full
admission checks.

## Verification gate

- Policy tests cover canonical roots, protected control components,
  duplicates, ceiling subset checks, and the outer sandbox.
- Linux adversarial tests prove an allowlisted command can modify the exact
  descriptor-bound root but cannot create a sibling root-level file or mutate
  unlisted repository metadata. They also cover hard-link rejection and
  retained-handle behavior after path replacement, cross-workspace mount-set
  rejection, read-only-root admission, and wide depth-first scans.
- Host admission probes the same writable-root mount profile before a model
  request.
- Spool tests cover schema-8 compatibility and policy-digest binding.
- Spool tests cover the aggregate retained-handle budget.
- Existing command, network, filesystem, daemon, and resident acceptance tests
  remain green.
- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- The exact PR head receives independent real-model review and every required
  GitHub check before merge.
