# WP-363 — Wire pure store/workflow error lines on daemon paths

## Outcome

Daemon goal acquisition, workflow failure/lease/completion, and MCP submit/control
mapping logs emit pure CLI kind lines for `GoalStoreError`, `TaskStoreError`,
`WorkflowError`, `WorkflowSubmitError`, and `DaemonWorkflowControlError`, clearing
half-landed `dead_code` on those formatters.

## Motivation

WP-302/309/311/320 published pure error kind lines. CLI daemon/MCP mapping paths
still logged only structured `error = as_str()` fields without consuming the pure
human lines.

## Acceptance

1. Resident goal acquisition logs pure `format_goal_store_error_kind_line` when the error is a store error.
2. Daemon workflow failure logs pure `format_workflow_error_kind_line`.
3. Workflow lease renewal and metadata completion retry log pure `format_task_store_error_kind_line` when the error is a store error.
4. MCP `map_submit_error` / `map_control_error` log pure submit/control formatters.
5. Structured `error` fields remain kind-only via `as_str`.
6. Local gates and independent review pass.
