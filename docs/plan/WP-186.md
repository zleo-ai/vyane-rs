# WP-186 — CLI human legacy `task status` pure formatter + tests

## Outcome

Human legacy detached `task status` (status.json path) goes through pure
`format_task_status` used by `print_task_status`. Unit tests drive the shipped
formatter with real `StatusFile` + displayed `TaskState`.

## Motivation

Durable status was locked in WP-180; the legacy status.json human path still
used only `println!`s, including the important displayed-state vs file-state
distinction (e.g. orphan `died`).

## Acceptance

1. `print_task_status` wraps `format_task_status`.
2. Printed state uses the **displayed** TaskState argument, not only the file state.
3. Optional workdir / finished / duration / ledger / error lines appear only when set.
4. Unit tests call the shipped formatter with real `StatusFile` values.
5. Local gates and independent review pass; no CI isolation train.
