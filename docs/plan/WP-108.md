# WP-108 — keep mixed daemon lanes independently schedulable

## Outcome

Run the mixed process/native daemon acceptance fixture on a two-worker Tokio
runtime so its control-plane pollers and Wiremock native-model target can make
independent progress after earlier acceptance runtimes in the same process
have torn down.

Production daemon, lane, polling, and timeout behavior do not change.

## Failure evidence

PR #61 run `30514538746` at commit
`f8fae0a5b1df33dc13e6118969b035212f45ddc2` passed coverage, macOS, MSRV, and
release-gate. Ubuntu then ran
`mixed_process_and_native_lanes_run_concurrently_in_one_daemon` inside the
serialized `daemon_agent_acceptance` binary. Its two terminal pollers each had
a 15-second total budget, but the first request timeout did not fire until
roughly 90 seconds had elapsed. The daemon log contained only its successful
listen message.

Twenty exact fresh-process repetitions passed under an external 30-second
guard. The failure is therefore tied to runtime scheduling after the earlier
acceptance fixtures, not to a deterministic production lane assertion.

## Acceptance

1. The fixture's control-plane and mock-target tasks can progress on
   independent Tokio workers.
2. Existing 15-second terminal budgets and all assertions remain unchanged.
3. No production code or CI process boundary changes.
4. Repeated exact and full-binary normal runs, coverage, formatting, Clippy,
   MSRV, release gate, parity, independent review, PR CI, and exact
   merged-main CI pass on immutable heads.
