# WP-270 — Pursuit status tokens on resident goal settlement log

## Outcome

Resident goal pursuit settlement diagnostics emit `PursuitStatus::as_str`
tokens (and durable `final_goal_status` tokens) instead of Debug `?` formatting.

## Motivation

`PursuitStatus` already publishes stable snake_case tokens (domain Display).
The daemon still logs `status = ?outcome.status`, which is Debug-shaped and
can drift from the operator vocabulary used by CLI pursue output.

## Acceptance

1. `daemon_goal` settlement `tracing::info!` uses
   `status = outcome.status.as_str()` (not `?outcome.status`).
2. When logged, `final_goal_status` uses `GoalStatus::as_str` (or equivalent
   Display token path), not Debug.
3. Local gates and independent review pass; no CI isolation train.
